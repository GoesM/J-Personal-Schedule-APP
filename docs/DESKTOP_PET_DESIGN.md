# J人桌宠：需求对齐草案

更新：2026-11-12。此文保留产品需求与验收依据。1.8.0 已按此实现；实际使用、构建和平台边界见 DESKTOP_PET.md。

## 用户已经明确的要求

- Windows 和 Linux 桌面显示；Linux 目标为 Ubuntu，具体版本及桌面会话待验收时确认。
- 角色位置仅由用户拖动改变，取消自动游走、随机位移和自动回位；平时只做原地动作。显示器移除等导致角色不可见时，可做必要的屏幕边界恢复。
- 用户拖动移动时播放行走/移动动画，腿和手臂应有自然的分肢动作；停拖后停步，放开后短暂收势并留在释放位置。
- 新增 TODO 保存成功后有独立反馈动作；完成 TODO/日程保留庆祝动作。
- 清单弹窗按可用屏幕空间自动选择位置，始终避开人物及其动作范围。
- 简单清单预览今日 TODO、日程和长期 TODO；支持勾选完成和快捷新增。
- 沿用 J人形象设计中的八位 J 型角色。
- 第一版就完成八位角色的完整动作，不以一位样例或整体平移动效作为最终交付。
- 主动提醒使用无声气泡，并支持稍后提醒。
- 形象、动作、源素材统一在 `../../J人形象设计/` 维护；正式桌宠功能和发行物在本项目维护。

## 建议采用的第一版体验（待继续对齐）

平时在用户放置的位置原地呼吸、眨眼、轻微摇摆；没有自动行走或活动强度设置。超过拖动阈值后角色跟随指针移动并进入行走状态，速度和方向参考拖动速度与方向；按住不动时停步，松开后收势回到待机。原地肢体反馈不改变桌宠窗口位置，动画不抢键盘焦点。

点击角色打开/收起清单，拖动超过阈值后不触发点击。清单有“今日 / 长期”两个标签，默认展示最多五项，再查看全部。可以固定清单使其常驻；固定不会使角色移动，若角色被拖到清单附近，清单仍必须避让。

### 弹窗避让规则

- 参照桌面右键菜单，依次尝试角色右侧、左侧、上方、下方；优先保持当前仍可用的位置，避免反复跳动。
- 按人物所有动作的最大可见边界（包括手臂、道具）加安全间距判断遮挡，不只判断脚底坐标；清单不可与这个区域相交。
- 使用角色所在显示器的可用工作区，避开任务栏/面板，处理缩放和多显示器边界。
- 拖动期间暂时隐藏清单但保留输入内容、标签和固定状态，松手后在新位置重新展开；避免拖动中抢焦点和弹窗追着指针闪动。
- 空间不足时减少可见列表行数、提供内部滚动，保留标题和新增入口；仍无法容纳时收起清单并提供打开主程序入口，不能移动角色或覆盖角色来腾地方。
- 新增事项、切换标签、窗口尺寸变化及切换角色后重新计算。固定清单也以不遮挡为优先。提醒气泡遵循相同避让原则。

- 今日：分别标示日程和 TODO；日程保留开始、结束时间。进行中/即将开始的日程优先展示，TODO 中重要项优先；已结束但未完成的日程保留状态，不自动勾选。更早日期的未完成事项通过独立入口查看，不静默搬到今天。
- 长期：未完成事项按截止日期排序，逾期和今天截止清楚标记；无截止日期事项排在后面。已完成内容折叠，沿用原存储语义。
- 快捷新增：在当前标签新增今日 TODO 或长期 TODO；新建完整日程、复杂编辑和冲突处理进入主程序。
- 勾选：保存成功后庆祝，可撤销；失败保留原状态并提示。不得先动画庆祝再忽略保存错误。
- 新增反馈：今日/长期 TODO 成功写入本地后，播放与庆祝不同的“记下了/准备开工”动作（例如记一笔、点头或整理道具）。主程序和桌宠入口都触发；保存失败、重复提交、启动加载、云端拉取不触发。连续新增合并短反馈，不积压动画；不等待 Git 上传成功才反馈。
- 提醒采用无声短气泡，提供关闭和稍后提醒，不重复弹出同一到期提醒。建议日程开始前10分钟提醒一次、可稍后5分钟；长期事项在截止日首次打开时汇总提醒，具体频率仍可调整。
- 开启桌宠后，主窗口可以收起而桌宠继续运行；托盘保留打开主程序、显示/隐藏桌宠和完全退出。完全退出仍走已有保存/未同步检查。
- MBTI 跟随原仓库/分支同步的形象偏好；位置、大小、动画偏好、显示器、清单固定状态只保存在本机。

## 现状与实现路线

本地代码基于 1.7.3，使用 Electron，已有单实例限制和保存、Git同步、退出状态机。当前关闭窗口会退出应用，需要调整桌面生命周期。长期 TODO 使用独立分区存储，不能由桌宠创建一套平行任务库。

1. 增加桌宠窗口与清单窗口，由同一 Electron 主进程管理；继续复用主程序运行时。
2. 提取统一事项命令入口及状态广播，让主界面、桌宠共用保存队列与同步锁。桌宠只提交完成/新增命令，不直接读写 Git 文件或单独发起同步。
3. 同一设备保存后两个视图立即刷新；跨设备仍沿用启动拉取/手动 Git 同步，不宣称实时云同步。
4. 构建时从形象库生成带来源版本和校验值的只读资源副本。保持角色 ID、动作状态和锚点一致，禁止直接在日程 APP 内修补角色原图。
5. 桌宠平台桥接独立于已有 Android Native 协议；公共事项逻辑继续兼容 Android，本阶段不扩展 Android 悬浮窗。
6. 保留原应用 ID、数据目录、云端协议、Windows 固定启动器和发布维护规则。

模块规划与职责：`desktop/pet/` 管窗口、托盘、屏幕与受限消息；`src/pet/` 管清单和交互；`src/` 中提取事项服务；`scripts/` 增加形象资源同步及 Linux 构建。

## 动作质量与素材边界

当前形象库有 idle/sway/focus/celebrate/sleep/move 六态，均为整幅插画变换。现有 move 没有迈腿，sleep 不闭眼。可用于第一轮交互验证，但不应称为完整行走动画。

用户明确要求首版完成八位角色的完整动作。拟议验收动作：待机呼吸/眨眼、拖动起步、拖动中的左右行走/转向、松手收势、点击反馈、新增记录反馈、完成庆祝、原地休息。行走只由拖动触发，应有腿部迈步、手臂协调摆动和身体重心变化，按角色道具调整动作，不能用整图平移替代；保留既有外貌、衣服与道具。动作制作可以逐位推进，但正式首版按八位全部通过验收交付。

所有图像与动作代码归形象库维护。角色原画的来源记录和归属说明随资源保留。

## Ubuntu 支持边界

Windows 与 Ubuntu X11 / XWayland 是拟议优先验证路线。取消自动游走后，仍需验证用户拖动过程中的动画、置顶和弹窗自动避让。Electron 原生 Wayland 的常规 setPosition / setAlwaysOnTop 限制仍影响窗口定位；XWayland 是否可用需现场验证，不将“能打包 Linux”视为桌宠可用证明。无法使用兼容会话时，应明确报告具体受限行为。

依据：https://www.electronjs.org/docs/latest/api/browser-window

## 首版验收建议

- 透明区不拦截底层应用，角色可点击、拖动；拖动释放不误开清单。
- 静置、打开/固定清单、新增/完成事项均不改变角色位置；拖动结束不惯性滑行、不自动回位。
- 拖动起步/行走/转向/停步/收势自然；点击、新增反馈、庆祝能被拖动中断并合理结束。
- 八位角色逐个验收完整动作；道具、四肢不裁切，新增动作与完成动作可区分。
- 今日和长期 TODO 在两个入口新增成功均触发一次反馈，失败、加载与云端同步不误触发。
- 清单在屏幕四角、四边、中间，多屏与不同缩放下都不遮挡人物，新增行或固定后也遵循避让规则。
- 无声气泡支持稍后提醒；重启、同步、系统唤醒不会连续重复轰炸提醒。
- 今日与长期预览、开始/结束时间、截止日期、颜色与主程序一致。
- 主界面与桌宠同时操作、保存失败、同步中点击、冲突版本、跨午夜均保持正确。
- 主窗口收起后桌宠可用；托盘能恢复主界面和退出；完全退出沿用已有未同步提示。
- 多屏、缩放、拔掉显示器后，角色和面板不遗失在屏幕之外；暂停、隐藏时降低动画开销。
- Windows 实机与指定 Ubuntu 环境分别验收；记录具体会话类型及未通过项。
- 成品放在 `release/`；Windows 继续维护固定快捷方式，Linux 发行格式待 Ubuntu 环境确定。
