# 长期 TODO：数据协议与加载策略（1.3.0）

长期 TODO 与原有 `ops/*.json` 日程日志隔离。旧日程和单日 TODO 的结构不变，不对真实数据执行迁移、删除或重写历史。

## 文件布局

```text
本机 profile/
├─ longtodo-device.json              # 本机写入身份，不进入 Git，也不进入备份
└─ repo/
   ├─ ops/<uuid>.json                # 原有日程与单日 TODO
   └─ longtodo/<device-uuid>/
      ├─ index.json                 # 本设备当前版本指针与因果关系，不含内容/备注
      ├─ active.json                # 本设备未完成事项当前版本
      └─ completed/
         ├─ 2026-09.json             # 按本地完成月份保存内容；删除也在这里归档
         └─ 2026-10.json
```

每台设备拥有自己的 active / index / 月归档。一次 Git 合并将不同设备的文件合并，不让多台离线设备争写一个全局清单。安装包不携带写入身份；切换仓库和导入备份也不复制身份。

`active.json` / 月归档结构为 `{format:'j-longtodo-v2',operations:{[operationId]:operation}}`。操作包含 `id,itemId,parents,ancestors,at,item,deleted`。item 包含 `kind:'longtodo',title,ddl,notes,done,completedAt,important`；`date/start/end` 为空，`ddl` 可为空。完成时间首次勾选时写入 ISO 时间，编辑已完成事项的备注不会刷新完成时间；取消完成清空完成时间。

`index.json` 为 `{format:'j-longtodo-v2',heads:[...]}`。每个指针仅包含操作 ID、事项 ID、父版本、祖先 ID、修改时间、完成状态/时间、删除状态与内容所在 bucket。它保留本设备的当前因果头；不复制标题、备注或所有历史版本的内容。索引仍随事项数量和每个事项的修改次数增长，需要在未来大规模使用时评估索引压缩，但一次读取即可，无逐条桥接调用。

## 常规加载

1. 读取每台设备的一份轻量索引，按 itemId 合并并利用 ancestors 抑制旧版本。
2. 只为未完成的当前版本读取对应 active 文件。旧设备残留的已被其他设备完成版本覆盖的 active 内容不会载入。
3. 完成记录使用**完成日期**，不是 DDL。最近 7 天定义为本地今天及前 6 天。仅读取相关月份文件，不遍历旧月份。
4. 按月文件的读取与解析是整体的，但仅物化最近 7 天的当前完成版本；同月较早内容不进入日常列表。每个月只读一次，避免逐条 IO。
5. 已完成区域默认折叠，展开不触发全历史加载。未完成按 DDL 升序，无 DDL 独立显示。
6. 并发冲突例外：加载所有冲突 heads（即使某个是较早完成版本），以便用户明确处理，不静默丢弃一方。

## 保存、断电与多端冲突

保存采用串行事务：**先原子写内容 → 再原子写索引 → 最后清理 active 旧版本**。索引是事务的提交点。索引前断电留下的额外内容不会成为可见记录；索引后清理失败只留下可忽略的旧内容，下次保存再次清理。Native 的单文件临时写入与原子替换沿用现有实现。

`ancestors` 保留父版本的传递关系，因此较早完成内容不载入时，仍能判断远端完成/删除已覆盖旧端未完成版本。并发修改仍保留多个 heads；解决时新操作以所有 heads 为 parents。不能用时间较晚就覆盖另一台设备的版本，也不能删掉因果索引来压缩。

每个物理设备只写自己的 UUID 目录。不要复制 `longtodo-device.json` 给另一台设备，否则会形成同一个 writer 的并发文件修改。正常备份/导入不会复制它。月文件保留该月份的内容版本，不把全部已完成事项堆在一个文件。

## 备份与维护

新备份格式为 `j-schedule-v2`，包含原有 `operations` 与 `longTodoHeads`（所有当前长期 TODO 版本，包括更早已完成和回收站记录及其因果祖先 ID）。完整导出按需读取旧月份；日常启动/同步不这样做。历史细节仍可从 Git 或月归档读取，备份不复制每次中间修改的完整内容。

导入同时支持旧 `j-schedule-v1`；v2 长期版本写入导入设备自己的目录，保留 ID 和祖先关系，重复导入不会制造重复事项或复活被更新版本覆盖的旧记录。切换仓库使用同样的跨 profile 复制流程，保留旧目录和旧历史。

1.3.0 将 `longtodo/` 一并加入 Git，仍执行 commit → fetch/merge → checkout → push；未初始化仓库的退出检查也涵盖长期 TODO。所有使用长期 TODO 的客户端应更新到 1.3.0；旧版不显示或导出新类别。

`tests/long-store.test.mjs` 覆盖七日窗口、旧月份不读取、2,000 条旧完成内容仅两次读取、完成时间、恢复、备份、并发和故障提交点；`tests/git.test.mjs` 使用真实 smart HTTP 验证不同设备的归档同步与并发解决。
