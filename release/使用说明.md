# 下载与使用

[返回首页](../README.md) · [开发指南](../docs/DEVELOPMENT.md)

## 1. 下载客户端

前往 [GitHub Releases](https://github.com/GoesM/J-Personal-Schedule-APP/releases/latest)，在 Assets 中下载对应文件，**不必下载 Source code，也不必配置开发环境**。

| 平台    | 下载与运行                                                                | 要求                                        |
| ------- | ------------------------------------------------------------------------- | ------------------------------------------- |
| Windows | 下载 `J-Personal-Schedule-版本号-win.zip`，完整解压后双击 `J人小程序.exe` | Windows 10/11，x64                          |
| Android | 下载 `J-Personal-Schedule-Android.apk`，复制到手机并安装                  | Android 8.0+，较新的 Android System WebView |

客户端内置 Git 引擎，使用时无需另装 Git、Node 或 Java。Windows 包请保留全部文件，不要单独复制 EXE。当前 Windows 发行包没有可信发布者代码签名，可能出现未知发布者提示；请确认来源是本仓库官方 Releases，不要关闭系统安全防护。

Release 同时提供校验文件，可用 PowerShell 的 `Get-FileHash -Algorithm SHA256 文件路径` 核对。Android 仍需在不同真机上确认 WebView、触控、键盘和系统文件选择兼容性。

## 2. 先离线记录

不配置仓库也能使用本地模式。桌面默认七日视图，手机默认单日卡片；日期条覆盖所选基准日期前后各七天，可切换十五日总览。翻页箭头按当前视图移动一天、一周或十五天。

- **日程**：点击日期下的“＋日程”，填写日期及开始/结束时间。跨夜安排请拆成两条。
- **TODO / 提醒**：点击“＋TODO”，只指定日期，不填写时间。
- **编辑与完成**：点击事项正文编辑，点击前面的方框切换完成状态；表单中可设置重要、每周重复或复制事项。
- **删除与恢复**：删除会移入回收站，可恢复；重复安排展开后，各日期实例独立编辑。
- **搜索与备份**：搜索标题、地点或备注，可查看全部日期的结果。导出/导入 JSON 备份不会包含访问令牌。
- **工具入口**：桌面在侧栏；手机点击右上角“更多”进入设置、帮助、备份、回收站和冲突列表。

### 颜色规则（1.2.0）

| 颜色 | 含义                                        |
| ---- | ------------------------------------------- |
| 浅绿 | 已完成，包含当天和提前完成的事项            |
| 浅灰 | 未完成且已过期：日程按结束时间，TODO 按日期 |
| 浅黄 | 其他普通事项                                |
| 浅红 | 其他重要事项                                |

旧版本课程记录会保留，但现在按普通日程统一染色。颜色按设备本地时间更新；不会自动将过期事项标记完成。

## 3. 配置 Git 同步

需要了解私有仓库、HTTPS 仓库地址、分支及访问令牌的概念；实际同步由客户端完成，不必手动运行 Git 命令。

1. 在 Git 托管服务上创建一个**专用于日程的私有空仓库**，不要初始化 README、许可证等文件。
2. 获取该仓库的 HTTPS clone 地址，例如 `https://github.com/你的用户名/你的私有日程仓库.git`。用户名、路径按实际仓库填写；**不要使用这个公开源码仓库**。
3. 创建具备目标仓库内容读写权限的访问令牌，尽量只授权此仓库；不要使用账户密码。不同托管服务的令牌设置方式不同，以其官方说明为准。
4. 在应用设置中填写 HTTPS 地址、Git 用户名、访问令牌及分支（通常为 `main`）。若旧客户端预填作者账户或仓库，请全部替换为你自己的信息。
5. 点击“与云端同步”。在其他设备输入同一个仓库和分支，再同步即可。各设备可使用不同令牌，只要都有该仓库读写权限。

当前支持 HTTPS smart HTTP；不支持 SSH、需要交互认证的仓库或重定向。GitHub、Gitee 等服务是否可用还取决于网络、账户权限和仓库实际配置。

### 同步在做什么？

- **启动**：提交本机尚未提交的记录 → 拉取/合并远端，不主动推送。
- **同步按钮**：提交本机记录 → 拉取/合并远端 → 推送。
- **正常退出**：等待保存和同步完成，检查未提交或已提交但未推送的改动；你可选择先同步或直接退出。失败时可留在程序重试。

离线或鉴权失败不会清空本地记录。启动拉取不代表本机记录已经上传；请主动同步。系统强制结束进程或划掉 Android 后台任务无法保证触发退出检查。

多端同时编辑同一事项时会保留各版本，通过“版本冲突”选择要采用的版本；不会静默覆盖。推送被拒绝时可以再次同步，不会强制推送或重置你的数据。

## 4. 数据、隐私与升级

Git 同步无须自建应用后端，但仍依赖你选择的 Git 托管服务，并非“数据不经过服务器”。日程仓库是明文的，私有访问控制不等于端到端加密；托管服务商与仓库管理员可能读取记录。请勿记录密码等秘密，勿公开数据仓库。

访问令牌使用 Windows 系统加密或 Android Keystore 本地加密，不上传到数据仓库，也不进入备份。不要把令牌写入仓库 URL、Issue、截图或聊天中。Git 保留历史，删除卡片也不会从 Git 历史抹除敏感信息。

本地数据位置：

- Windows：`%APPDATA%/j-personal-schedule/data`。
- Android：应用内部 `files/data`。

建议定期导出备份。修改仓库或分支会切换独立目录并复制已有事项，旧目录保留；不会复制旧仓库 Git 历史。

升级前先备份。Windows 退出旧版，将新版完整解压到新目录运行，仍读取原用户数据；不要删除 AppData。Android 直接覆盖安装官方同签名 APK，**不要先卸载**。自行构建的 APK 若签名不同，不能覆盖官方包，请先备份再迁移。

## 5. 常见问题

- **同步失败**：先检查网络、仓库 HTTPS 地址、分支、用户名及令牌读写权限；避免 URL 中含凭据。需要重试时再次点击同步，本地数据会保留。
- **看不到其他设备改动**：确认两端使用完全相同的仓库与分支，源设备已经推送，目标设备已经拉取。
- **时间或颜色不对**：检查设备时钟与时区，再确认日程结束时间和完成状态。
- **没有弹出提醒**：目前没有系统通知、闹钟或后台定时同步；提醒事项展示在应用内。
- **Excel 导入**：目前不提供 XLSX 自动导入；支持本应用 JSON 备份。
