## 技术路线

共享界面使用原生 JavaScript / HTML / CSS，由 esbuild 打包。Windows 使用 Electron 宿主，Android 使用纯 Java WebView 宿主。两端内置 `isomorphic-git`，通过受限 Native 文件系统和 HTTPS 接口同步不可变操作日志，不依赖运行设备安装系统 Git，也不需要应用后端。

源码仓库与个人日程仓库必须分开。Git 引擎只提交配置的数据仓库，不把本项目源码、构建环境或签名材料推到日程仓库。

## 本地启动

需要 Node.js 24+、npm；Git 用于克隆和贡献源码。构建后的客户端不需要这些工具。

```powershell
git clone https://github.com/GoesM/J-Personal-Schedule-APP.git
cd J-Personal-Schedule-APP
npm ci --cache ./env/npm-cache
npm test
npm run build
npm start
```

`package-lock.json` 固定依赖；首次安装和打包可能需要联网获取 npm / Electron 组件。

| `scripts/`                               | 前端构建、Windows/Android 打包、校验和预览                |
| `tests/`                                 | 模型、表单、退出、双端 DOM 与真实本地 Git smart-HTTP 测试 |

## 构建客户端

### Windows

```powershell
npm run package:win
```

输出在 `release/`：免安装目录和 ZIP。若旧程序占用默认输出目录，先构建前端，再指定独立目录：

```powershell
npm run build
npx electron-builder --win dir zip --config.directories.output=release/windows-dev
```

不要终止用户正在使用的程序或清除用户数据来解决输出目录占用。当前没有可信发布者 Windows 代码签名。

### Android

需要 JDK（可使用 Android Studio 的 JBR）和 Android SDK，平台36.1、build-tools36.1.0。当前最低 API26、target35。脚本使用 aapt2、javac、d8、zipalign、apksigner，不依赖 Gradle。

```powershell
$env:ANDROID_HOME = '你的Android SDK目录'
$env:JAVA_HOME = '你的JDK或JBR目录'
npm run package:android
```

务必显式设置路径；脚本原有默认值是作者本机路径。aapt2 资源编译使用临时英文目录，输出仍在 `release/J人小程序-Android.apk`。

首次构建会在 `env/signing/` 生成自己的签名密钥。安全备份 `release.jks` 和 `password.txt`；同一签名才可持续覆盖升级。**私钥与密码绝不能提交源码或放进 Release**。贡献者自行构建的签名与官方不同，不能直接覆盖官方安装。

## 测试与预览

```powershell
npm test
npm run format
npm run build
node scripts/preview.cjs
```

预览地址为 `http://127.0.0.1:4173`，使用临时示例数据，不连接个人仓库。在另一个终端可运行离屏 Chromium 布局检查：

```powershell
node_modules/electron/dist/electron.exe scripts/ui-smoke.cjs
```

隔离原生烟测（不要省略测试参数）：

```powershell
node_modules/electron/dist/electron.exe . --smoke-test
node_modules/electron/dist/electron.exe . --exit-smoke-test
```

这些测试使用临时数据目录。正常 `npm start` 使用真实本地配置，**开发者不要在测试中填写真实令牌或个人日程**。APK 构建/签名通过不等于 Android 真机验收，发布前应检查安装、系统栏、键盘、备份、退出和跨端同步。

## 欢迎 PR

1. Fork 并新建功能分支，每个 PR 聚焦一个问题。
2. 说明复现步骤、修改原因及验证方式；UI 改动请附桌面/手机的脱敏截图。
3. 修改日期、颜色、冲突或同步规则时补测试；新增 Native 方法须同时实现 Windows 与 Android。
4. 保持数据格式向后兼容；不要静默丢弃冲突、强制推送或清除本地数据。
5. 运行测试与格式化，保留第三方许可证，不提交构建产物、真实数据、令牌或签名材料。

公开仓库目前尚未指定项目开源许可证；第三方依赖按其各自许可证使用。若需要特定授权，请先联系维护者，不要仅因源码公开就假定有某种许可。

## 发布约定

源码进入 Git，ZIP/APK 通过 GitHub Releases 分发；不要把大型安装包加入 Git 历史。版本号需同步 `package.json`、lockfile 和 Android Manifest，Android `versionCode` 递增，签名保持稳定。附当前发行文件的 SHA256 与更新摘要，说明真机验证和已知限制。

上传前检查 `.gitignore`、待提交文件与安装包内容，排除 `env/`、凭据、数据日志、签名私钥和本地验收记录。Windows 完整 ZIP、官方 APK、使用教程和必要的第三方许可一起发布。
